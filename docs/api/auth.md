# 单机安全边界

当前版本不引入账号体系和多租户隔离。安全边界建立在**网络可达性**上，而不是用户身份认证。

## 边界模型（用户 2026-10-03 定调）

本工具是**本机单用户 IDE**：后端与前端都只监听 `127.0.0.1`，局域网物理上无法连接。因此不引入写令牌 —— 一次「谁有资格写库」的身份认证，在只有一个人的机器上没有对应威胁，而它带来的「前端怎么拿到令牌」链路本身就是故障源（曾因 vite 读到另一个实例遗留的过期 `runtime-token`，导致读接口正常而所有写接口 401，表现为「界面加载得出来但点不动」）。

## 仍然保留的防护

| 防护 | 防的是什么 | 为什么不能删 |
|---|---|---|
| Host 校验（`validHost`） | DNS rebinding：恶意域名解析到 127.0.0.1 后，浏览器发出的请求 Host 是域名 | 浏览器里任意网页都能向 `127.0.0.1` 发请求 |
| Origin 校验（`validOrigin`） | CSRF：恶意网页借用户浏览器改库 | 同源策略挡得住「读响应」，**挡不住「发请求」** |
| 请求体上限 8 MB | 内存耗尽 | — |
| 导出目录预登记 | 任意路径写入 | — |
| provider 凭据只存后端 | 泄漏进前端 bundle 或日志 | — |

跨站请求（非本应用 Origin）的写操作返回 403 `invalid_origin`；Host 不合法返回 400 `invalid_host`。

## 扩大监听地址前必须重审

`apps/web3/vite.config.ts` 的 `server.host` 与 `scripts/dev.sh` 的后端 `-addr` **必须**保持回环。一旦改成 `0.0.0.0`：

- 局域网任何设备都能读写本机数据库，没有任何凭据能拦住；
- CSRF 防护挡不住同网段的直接请求（同源策略不适用）；
- 此时必须把写令牌加回来（或引入真正的账号体系）。

改动这两个值时，按代码改动对待，走 review。
