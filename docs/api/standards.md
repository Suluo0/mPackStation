# 接口设计规范

> 本文件规定 mPackStation 前后端接口的**应然标准**。实现与本文档冲突时，**改实现**。
>
> 配套文档：[`contract.md`](./contract.md) 是逐接口的契约；[`dto.md`](./dto.md)、[`errors.md`](./errors.md)、[`auth.md`](./auth.md) 分别定义数据结构、错误和鉴权；实现状态见 [`implementation-status.md`](./implementation-status.md)。
>
> 状态：初版，部分条目标记为 `待确认`，确认后去掉标记。

---

## 1. 定位与优先级

实现过程中遇到规范未覆盖或彼此冲突的情况，按以下顺序裁决：

1. **HTTP / RFC 语义** —— 状态码、方法语义、头部用法以 RFC 为准
2. **本文档** —— 项目级的统一约定
3. **`contract.md`** —— 单接口的参数和响应细节；不得无理由改变全局规则
4. **架构设计文档** —— 只作为意图参考，不作为实现依据
5. **现有代码** —— **优先级最低**。代码是现状，不是标准

最后一条是关键：不允许因为"代码已经这样了"而修改规范。要改就改代码。

## 2. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 路径 | 小写，复数资源，多词用连字符 | `/api/packs/{packId}/delivery-checks` |
| 路径参数 | camelCase，与领域 id 同名 | `{packId}` `{documentId}` |
| 查询参数 | camelCase | `packVersionId` `recent` |
| JSON 字段 | camelCase | `mcVersion` `createdAt` |
| 错误码 | snake_case，`<领域>_<问题>` | `quest_cycle` `import_preview_expired` |
| 领域 DTO | Go 结构体必须带 `json` tag | `json:"packId"` |

**禁止**：把 Go 结构体直接序列化（无 json tag 会输出 `ID` `PackID` 这类字段名）。偏差记录在日期化审计中。

## 3. 请求

### 3.1 传输

- 写请求的 `Content-Type` 必须是 `application/json`，否则 **415**
- 请求体必须是合法 JSON，解析失败 **400**
- 请求体上限 8 MB，超出 **413**

### 3.2 参数放置

| 类型 | 放置位置 | 规则 |
|---|---|---|
| 资源标识 | 路径参数 | 必填，缺失应 404 而非 400 |
| 过滤、分页、排序 | 查询参数 | 全部可选，有默认值 |
| 创建/更新的业务字段 | 请求体 | —— |
| 并发控制 | 请求头 | `If-Match` |
| 幂等 | 请求头 | `Idempotency-Key` |

### 3.3 分页

- 列表接口**统一返回信封**，不搞两种形状：

```json
{"items": [], "next_cursor": null, "total": 0}
```

- `total` **必须返回整数**，不允许缺省
- 接口不支持分页时 `next_cursor` 恒为 `null`，契约里逐条标注“是否分页”
- 分页参数统一命名：`limit`（默认 20，上限 100）、`cursor`（不透明字符串）

### 3.4 幂等

- **所有会产生副作用的 POST 必须支持 `Idempotency-Key` 请求头**
- 重复请求 + 相同输入 → 返回原结果（同一状态码 + 同一响应体），不是错误
- 重复请求 + 不同输入 → **422** `idempotency_conflict`
- 响应体用 `reused: true` 标记这是重放结果

### 3.5 并发控制

- 带 revision 语义的写操作（内容草稿、任务书草稿）**必须**用 `If-Match`
- 值用带英文双引号的 revision 号：`If-Match: "3"`
- 前置条件失败 → **412** `revision_conflict`

## 4. 响应

### 4.1 成功状态码

| 状态码 | 适用 |
|---|---|
| 200 OK | 查询、成功执行并返回结果的更新 |
| 201 Created | 创建资源成功，响应体是新资源 |
| 202 Accepted | 已接受并入队，处理未完成，响应体含 `taskId` |
| 204 No Content | 删除成功，或执行成功但无内容可返回。**响应体必须为空** |

### 4.2 时间

- 一律 **ISO 8601 UTC**（RFC 3339），例：`2026-08-30T03:58:54.252Z`
- 持久化用 unix 毫秒，序列化时才转 ISO 8601
- 前端 zod 必须用 `z.string().datetime()` 校验，不允许只写 `z.string()`

### 4.3 可选字段

- 可选字段无值时返回 **`null`**，不省略键
- 前端 schema 用 `.nullable()`，不用 `.optional()`
- 目的：消费方不需要判断 key 是否存在

### 4.4 领域 DTO 一致性

**同一领域概念在所有接口必须返回同一结构。**

任务领域必须归一为 [`dto.md`](./dto.md) 的 `Task` 结构；当前偏差记录在实现状态和日期化审计中。

### 4.5 枚举

- 后端只输出契约里声明过的取值
- 未映射的取值（如新出现的任务类型）**必须显式声明为开放字符串**，不允许静默输出空串
- 前端对开放枚举必须带兜底展示

## 5. 校验

### 5.1 分层

| 层 | 负责 | 失败码 |
|---|---|---|
| HTTP 层 | 结构校验：JSON 解析、字段类型、必填缺失 | **400** |
| service 层 | 语义校验：业务规则、跨域引用、状态合法性 | **422** |
| 存储层 | 不变量：外键、唯一约束 | **500**（属服务端缺陷，不应暴露给调用方） |

**区分 400 与 422 的判据**：请求"格式不对"是 400，"格式对但业务上不成立"是 422。例如：

- `mcVersion` 字段缺失 → 400
- `mcVersion` 填了 `"1.21.8"` 但加载器不支持该版本 → 422
- 导入链接不是 https → 400
- 导入链接是 https 但域名不是 curseforge.com → 422

### 5.2 出参校验

- 后端 DTO 必须有 json tag，禁止裸结构体序列化
- 前端**所有**响应必须过 zod，不允许 `z.unknown()` 长期存在
- `z.unknown()` 只允许作为临时过渡，且必须在契约里标注理由与 TODO

### 5.3 校验失败详情

语义校验失败时，`error.details` **必须**携带结构化的 `issues` 数组：

```json
{
  "error": {
    "code": "quest_cycle",
    "message": "任务书存在环",
    "request_id": "req-...",
    "details": {
      "issues": [
        {"code": "cycle_detected", "severity": "error", "path": "edges[3]", "message": "节点 A -> B -> C -> A 构成环"}
      ],
      "affectedMods": ["mod-..."]
    }
  }
}
```

`details` 不允许是无结构的空对象。

## 6. 错误与异常

### 6.1 错误信封

```json
{"error": {"code": "...", "message": "...", "request_id": "...", "details": {}}}
```

四个字段都**必须存在**。`details` 无内容时为 `{}`，有内容时按 §5.3。

`message` 面向开发者（英文、可诊断），不面向终端用户。前端需要自行翻译。

### 6.2 状态码决策表

| 状态码 | 含义 | 本项目中的用途 |
|---|---|---|
| 400 | 请求结构错误 | JSON 解析失败、字段类型错、必填缺失、参数格式非法 |
| 401 | 未认证 | 写请求缺少或令牌错误 |
| 403 | 已认证但被拒 | Origin 不在白名单、导出目录未登记 |
| 404 | 资源不存在 | 包/任务/Provider 资源未找到 |
| 405 | 方法不允许 | 路径存在但方法不匹配 |
| 408 | 请求取消或超时 | 客户端断开、上下文超时 |
| 409 | 资源状态冲突 | 状态流转非法、租约失效、一次性凭证已消费 |
| 410 | 资源已永久消失 | 导入预览过期 |
| 412 | 前置条件失败 | `If-Match` 的 revision 已陈旧 |
| 413 | 请求体过大 | 超过 8 MB |
| 415 | 媒体类型不支持 | `Content-Type` 不是 `application/json` |
| 422 | 语义校验失败 | 业务规则不成立、校验未通过、幂等键冲突 |
| 429 | 限流 | 预留，暂未实现 |
| 500 | 服务端未分类错误 | 兜底 |
| 501 | 未实现 | 功能占位 |
| 502 | 上游不可用 | CurseForge / Modrinth 不可达 |
| 503 | 本服务未就绪 | 依赖未装配、鉴权未配置 |

### 6.3 错误码粒度

**采用细粒度错误码。** 通用错误（如 `validation_failed`）无法让调用方分支处理，只在兜底时使用。

命名格式 `<领域>_<问题>`，领域前缀包括：

| 前缀 | 领域 |
|---|---|
| `pack_` | 整合包 |
| `mod_` | 模组 |
| `content_` | 内容文档 |
| `quest_` | 任务书 |
| `import_` | 导入 |
| `build_` | 构建 |
| `release_` | 发布 |
| `task_` | 任务 |
| `provider_` | 外部平台 |
| `export_` | 导出目录 |

示例：`pack_version_conflict`、`content_invalid`、`quest_cycle`、`quest_invalid_reference`、`import_preview_expired`、`build_blocked`。

`待确认` —— 这条决定了错误码改造的工作量，确认后铺开。

### 6.4 可重试性

契约里每个错误码必须标注 `可重试` / `不可重试`：

- **可重试**：502、503、408、429，以及 `task_lease_lost`
- **不可重试**：400、401、403、404、405、410、412、415、422、501
- 409 视具体错误码而定，逐个标注

前端默认只在"可重试"时提供重试入口。

### 6.5 异常处理纪律

- **不允许**用 HTTP 200 包裹业务失败。失败必须用 4xx/5xx
- **不允许**吞掉错误返回空列表/空对象
- **不允许**为了通过测试放宽校验或跳过恢复路径
- 上游 Provider 失败必须映射为 **502**，不能透传上游原始状态码

## 7. 鉴权

- 所有非 GET 请求需要 `X-MPack-Token` 头
- 令牌在**服务启动时生成**随机值，写入 `data/` 下的文件（权限 0600）
- **禁止**硬编码任何令牌值，包括开发环境
- 前端开发服务器启动时从该文件读取并注入；生产由安装包注入
- 令牌缺失时返回 **401**，未配置时返回 **503** `auth_not_configured`

> 禁止使用硬编码凭据（包括 `test`）作为运行时兜底。当前是否达标以 [`auth.md`](./auth.md) 和实现状态表为准。

## 8. 一致性要求

1. 新增接口必须同步更新 `contract.md`，否则防漂移检查失败
2. 修改响应结构必须同步前端 zod schema
3. 同一概念在不同接口的字段名必须一致（`packId` 不能有时叫 `packID`）
4. 领域 DTO 只能有一份定义（见 §4.4）

## 9. 决策记录

| 编号 | 决策 | 理由 | 状态 |
|---|---|---|---|
| D-1 | 列表统一用信封，不支持分页时 `next_cursor` 恒 `null` | 两种返回形状会让调用方无法统一处理 | 已定 |
| D-2 | 乐观锁用 412 而非 409 | RFC 7232 中 412 专用于前置条件失败；409 语义过泛 | 已定 |
| D-3 | 400 与 422 按"结构 vs 语义"划分 | 调用方能据此区分"改请求"和"改数据" | 已定 |
| D-4 | 可选字段返回 `null` 而非省略键 | 消费方无需判断 key 存在性 | 已定 |
| D-5 | 错误码细粒度 | 通用错误码无法支撑前端分支处理 | `待确认` |
| D-6 | 幂等重放返回原结果而非报错 | 这是幂等的定义 | 已定 |
| D-7 | 领域 DTO 全局唯一 | 多套结构必然导致解析失败或 unknown 绕过 | 已定 |
| D-8 | 启动生成令牌，禁止硬编码 | 硬编码凭据是缺陷不是便利 | 已定 |
| D-9 | 契约先发布，代码分批追平，用符合度清单跟踪 | 等代码全改完才有文档 = 文档永远落后 | `待确认` |
