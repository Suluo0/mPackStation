# 关系态原型 · JEI 能力对等（方向 C）

- 状态：**可点原型，待评审**（2026-10-03）
- 跑法：在本目录起一个静态服务打开 `index.html`
  ```bash
  cd docs/active/design/prototype/relation-lens
  python3 -m http.server 8931 --bind 127.0.0.1
  # 打开 http://127.0.0.1:8931/index.html
  ```
- 这不是视觉稿，是**能点的东西**：1334 物品 / 1291 配方 / 147 标签全量真实数据，和 `apps/web3` 用的是同一批目录导出。

## 1. 这份原型要回答什么

「把那个仿 JEI 的静态页一比一搬进项目」有两种理解，结论完全不同：

| | 理解 A：搬能力（本原型） | 理解 B：搬像素 |
|---|---|---|
| 皮肤 | 整张丢掉，用 workbench 的暖纸 + ember 语言重画 | 沿用 JEI 的深色游戏皮 |
| 结构 | 关系态 = 编辑区的一个透镜，和索引/链路/魔改共享焦点 | 独立路由 / 独立页面 |
| 代价 | 需要先定义「配方卡原子」 | 直接抄样式最快 |

JEI 那套皮是给「游戏内、没有文字、鼠标悬在 18px 槽位上」这个场景长的；web3 是「有 URL、有键盘、有面板体系的工作台」。所以本原型按 A 做，**一比一的是能力，不是像素**。

## 2. 与既有 `docs/active/design/jei-recipe-browser.md` 的差异

那份方案（2026-09-21）主张**独立路由 `/packs/:id/recipes`** + 左物品列表 / 中配方画布 / 右收藏。本原型主张把它做成**关系态透镜**，理由是：

1. 独立路由意味着**两套配方渲染语言、两套筛选器、两套物品卡**——以后每改一次都要改两遍。
2. 项目已经有链路引擎和 `ChainView`。**把配方卡定义成链路图的节点**，链路引擎的「选路」就自动成了 JEI 的「换一条配方」，能力反而更容易对齐。
3. 关系态本来就是 web3 里唯一完全没动过的透镜（`ModeGraph.tsx` v0 只有两个清单列），它缺的正是这层能力。

本原型把这条差异做成了可核查的形态：**同一份配方卡原子，画布视图下钻、清单视图浏览**。

## 3. 两个核心概念

**① 配方卡原子**：`recipeCard()` 一个函数、一套 DOM、一种视觉，画布与清单共用。它按配方类型渲染四种形态——有序 3×3 / 无序填槽 / 单输入机器 / 规则卡。以后链路图的节点直接复用这个函数。

**② 两层焦点**（JEI 能力里最容易被换皮时顺手删掉、删了就不算一比一的东西）：

- **持久层**：当前物品，住在 URL（`?item=`），是唯一的「我在哪」。
- **瞬态层**：当前配方（`?r=`）、当前高亮槽位、槽位候选游标——下钻/换配方/轮换候选只动这里。
- 下钻（点材料槽）把材料推入 `?path=`，面包屑就是操作历史，`Esc` / `↰ 返回上层` 回落。

## 4. 能力对照表（可核查判据）

判据都写成「在原型里点哪里能看见」，评审时逐条核对，不靠描述。

| # | JEI 能力 | 落点 | 判据（怎么验） |
|---|---|---|---|
| 1 | 物品索引 + 搜索 | 清单视图「匹配物品」栅格 + 索引态 | 搜 `#planks` → 11 个物品 |

| 9 | 配方类型分类（catalyst 对等） | 顶部分段筛选器（全部/工作台/切石机/熔炼类/锻造台/特殊·规则） | 每个分段后有真实条数：888 / 250 / 112 / 27 / 14 |
| 10 | 合成 / 机器 / special 三类渲染 | 有序网格 / 单输入机器箭头 / **规则卡** | 特殊·规则分段 → 14 张规则卡，槽位是真实图标 |
| 11 | special 模板（12 种 + 陶罐 + 纹饰） | `RULE` 表，14 条全收录 | 装饰陶罐卡 → 陶片 `1/23` + 红砖 → 装饰陶罐 |
| 12 | special 在物品侧可查 | 规则卡的产物登记进反查索引 | 搜「旗帜」→ 旗帜的「作为产物」里能看到 `banner_duplicate` |
| 13 | 快捷键帮助（`?`） | 顶部 `? 快捷键` 浮层 | 表内 11 条，含键位让位说明 |
| 14 | 输入框内不劫持字母 | keydown 先判 `input/textarea` 直接返回 | 在搜索框里打 `rudf` 不触发任何动作 |
| 15 | 空态 / 断点诚实 | 区分「目录无配方」与「有配方但读不出边」 | `minecraft:dirt` → 采集类诚实文案，不显示 `0` 当未知 |
| 16 | 缺失图标不造假 | 首字占位 + 右栏注明 75 项 | 树叶/床/旗帜等显示首字方块，不是假图标 |
| 17 | URL 是单一事实源 | 焦点/视图/模式/筛选/翻页全在 hash，状态条实时显示 | 复制状态条里的 hash 到新标签页 → 回到同一状态 |

**故意不做**（是 JEI 在游戏里的妥协产物，搬进网页只会变成反直觉设置项）：

| 放弃项 | 理由 |
|---|---|
| 分页 / 滚动双导航 | 游戏里没有滚轮才需要分页。网页里位置感用「位置 3/10」就够 |
| 1–3× 界面缩放 | 浏览器自带缩放，自己再做一层只会打架 |
| 面板宽高上限滑杆 | 同上，属于「窗口不可调」年代的补丁 |

## 6. URL 契约（对齐 `app/url.ts`，不制造同义参数）

| 参数 | 含义 | 备注 |
|---|---|---|
| `?mode=` | 透镜 `index\|graph\|chain\|edit\|quest` | 与 `url.ts` 的 `MODES` 同名同义，原型默认 `graph` 时省略 |
| `?item=` | 焦点物品 | 与 `useFocus` 同一契约 |
| `?path=` | 下钻路径（逗号分隔） | **新增**，链路/魔改可复用 |
| `?rmode=` | `recipes\|uses` | **新增**，刻意不叫 `mode` |
| `?view=` | `canvas\|list` | **新增**，只作用于关系态 |
| `?seg=` `?q=` `?r=` | 类型分段 / 查询 / 配方序号 | **新增** |

## 8. 要在 `apps/web3` 落地，建议这样切

1. **先抽原子**：把 `recipeCard()` 从本原型挪成 `apps/web3/src/recipe/RecipeCard.tsx`（+ `normalizeRecipe.ts`），`ModeGraph`、`ChainView`、清单视图三处共用。这是整件事的地基，做在前面能省掉后面所有重复。
2. **重写关系态**：`ModeGraph.tsx` → 画布（下钻）+ 清单（浏览）两种排布，砍掉现在那两个平铺清单列。
3. **补 URL 契约**：`url.ts` 加 `path/rmode/view/seg/r`，按上面的表；`useFocus` 不动。
4. **规则卡模板表**：`RULE` 表进 `apps/web3/src/recipe/ruleTemplates.ts`，带 `mcVersion`，模组 special 后续可追加。
5. **收藏 / 最近落后端**：本原型为演示暂存 localStorage，落地必须走后端 + URL（与「不留假 affordance、URL 单一事实源」一致）。

## 9. 本原型没做的（诚实清单）

- 收藏/最近未接后端，仅 localStorage（原型期），已在右栏明示。
- `路径` 未做「按住 Alt 点槽位在新分支打开」——下钻永远是替换当前分支。
- Uses 反查在内存里做，未验证在真实大整合包（数万配方）下的性能；本批 1291 配方无压力。
- 模组 `SpecialRecipe` 自动网格没做（数据里就没有），规则卡只覆盖原版 14 条。
- 未与 `ChainView` 做视觉对齐实测（原型里链路态是占位提示，没有真的把卡塞进链路图）。
- 未做虚拟滚动；清单是「每批 60 条」增量渲染。
