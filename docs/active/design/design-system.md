# mPackStation · Product UI Design System

这不是某一个页面的样式表，而是整套产品界面的共同语法。所有页面先遵守这里的结构和排版，再添加页面专属内容。

## 1. 设计定位

**Design read**：面向整合包作者的桌面创作工作台。气质要安静、可靠、有工具感，像一个经过整理的工作台，不像营销页，也不像默认后台模板。

设计拨盘：

- 变化度 `6/10`：允许有品牌图形和深色编辑画布，但结构保持稳定。
- 动效 `3/10`：只做反馈和状态变化，不做展示性动画。
- 信息密度 `6/10`：信息多，但通过分组和留白建立节奏。

## 2. 页面构图

### 2.1 外壳

- 侧栏：`184px`，收起后 `64px`。
- 顶栏：`56px`，只放当前上下文、帮助、通知和用户菜单。
- 内容最大宽度：`1280px`，页面两侧自动留白。
- 内容水平内边距：桌面 `32px`，窄屏 `20px`。
- 桌面页面使用 12 列网格；主区和辅助区的比例优先使用 `8/4` 或 `9/3`，不要平均切成很多小块。

### 2.2 首屏原则

首屏只回答三个问题：

1. 我现在在哪个包或哪个模块？
2. 当前最重要的事情是什么？
3. 我下一步可以做什么？

首屏不能同时放多个同权重的标题、主按钮或大卡片。一个页面只能有一个第一视觉焦点。

## 3. 排版系统

### 3.1 字体

优先使用本地系统字体，避免网络字体导致布局抖动：

```css
font-family: "Noto Sans SC", "Microsoft YaHei", "Segoe UI", sans-serif;
```

英文和数字使用同一无衬线家族；数据数字统一使用：

```css
font-variant-numeric: tabular-nums;
```

不要在同一个产品里混用多套展示字体。Minecraft 气质通过图形、封面和材质表达，不通过像素字体铺满界面。

### 3.2 层级

| 层级 | 字号 / 行高 | 字重 | 使用位置 |
|---|---:|---:|---|
| Display | 36 / 44 | 750 | 开始页主标题，最多两行 |
| H1 | 28 / 36 | 750 | 页面标题 |
| H2 | 20 / 28 | 700 | 主区块标题 |
| H3 | 15 / 22 | 700 | 卡片标题、列表组标题 |
| Body | 14 / 22 | 500 | 默认正文、表格内容 |
| Label | 12 / 18 | 600 | 标签、字段名、辅助说明 |
| Caption | 11 / 16 | 500 | 时间、来源、次级元数据 |
| Data | 20 / 24 | 700 | 健康数字、进度百分比 |

排版规则：

- 一级标题和副标题之间 `8px`。
- 区块标题和内容之间 `16px`。
- 标题不要使用全大写、过度字距或渐变文字。
- 一行正文尽量不超过 65 个中文字符。
- 一个页面最多使用 Display、H1、H2、Body、Caption 五种视觉级别。
- 主标题宁可缩短文案，也不要靠强制断行制造气势。

## 4. 间距、颜色和形状

### 4.1 间距

只使用这组刻度：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`。

- 4：图标与文字的最小间隙
- 8：同一组件内部
- 12：列表行、标签组
- 16：卡片内部和区块间距
- 24：主要区块之间
- 32：页面标题和主体之间
- 48：首屏或页面级留白
- 64：开始页 Hero 的最大留白

### 4.2 颜色职责

产品只能有一个品牌主色。当前 workbench 语言使用 ember 橙；如果切回参考图的紫色品牌，必须整页替换主色，不能橙紫并列争夺视觉焦点。

- 品牌主色：主按钮、当前导航、选中态、关键焦点
- 信息青：连接状态、辅助信息、可更新
- 成功绿：已解决、校验通过、打包成功
- 警告金：需要注意但不阻塞
- 错误红：失败、冲突、崩溃、阻塞
- 中性色：背景、卡片、分隔线、次级文字

禁止：

- 用绿色作为普通入口按钮
- 用红色表达普通强调
- 每个卡片使用不同渐变
- 大面积彩色背景和高强度阴影同时出现

### 4.3 形状

- 页面卡片：`14px`
- 按钮、输入框、选择器：`9px`
- 状态胶囊和头像：`999px`
- 同一页面不混用多套圆角规则。

阴影只用于浮起层级；普通卡片优先使用边框和留白区分，不要让所有东西都像悬浮面板。

## 5. 菜单和导航

### 5.1 侧栏菜单

- 一级菜单只放用户能独立理解的工作域。
- 模组搜索必须在整合包上下文内，不作为全局入口。
- 当前项使用浅色品牌底和品牌文字，不使用强烈渐变块。
- 菜单项高度 `40px`，图标宽度固定，文字基线对齐。
- 侧栏底部只放设置、帮助或收起操作。

### 5.2 页面内导航

- 选项卡适合同一工作域的平级内容。
- 步骤条只用于有顺序的交付流程，不用于普通分类。
- 左侧 Rail 适合编辑器和长流程，右侧 Inspector 适合当前选中对象。
- 不要同时使用侧栏、页签、步骤条和面包屑表达同一层级。

## 6. 按钮

一个页面最多一个主 CTA 区域。

- Primary：完成当前页面的核心动作，例如“应用到包”“开始打包”。
- Secondary：次级动作，例如“保存草稿”“测试连接”。
- Quiet：取消、查看详情、打开目录等低风险动作。
- Danger：删除和不可逆操作，必须配确认文案。

按钮文案使用“动词 + 对象”，如“添加模组”“查看详情”“导出整包”，不要使用含糊的“确定”“继续”。

## 7. 表格和列表

表格的目标是快速扫读，不是展示所有数据。

- 表头字号 `12px`，颜色使用 muted。
- 行高 `52px`，密集操作表格最低 `44px`。
- 数字列右对齐并使用等宽数字。
- 状态列固定宽度，优先保留待处理信号。
- 同一行最多展示 2 个状态信号，其余收进详情或 Tooltip。
- 行 hover 使用浅色背景，点击整行时必须有明确的可打开语义。
- 不在每一行都放完整边框；使用分隔线和留白即可。
- 空表格要告诉用户如何产生第一条数据，不显示“暂无数据”孤句。

## 8. 卡片

卡片只有在它表达独立层级、独立状态或独立操作时才使用。

推荐结构：

```text
标题行
  标题 + 可选说明              右侧一个动作
内容区
  主要信息                    次级信息
底部
  状态或下一步动作
```

卡片规则：

- 一张卡片只承担一个主要任务。
- 同一组卡片保持相同内边距和标题基线。
- 卡片内容不足时不要强行拉高卡片。
- 连续列表优先使用一个容器加分隔线，不要每行都套卡片。
- 开始页允许使用更强的图形卡片；业务页应减少装饰。

## 9. 模态框和抽屉

### 9.1 模态框

只处理短流程：新建、导入、删除确认、少量设置。

- 宽度：短表单 `480px`，复杂表单 `640px`。
- 标题明确说明动作和对象。
- 表单字段垂直排列，标签和输入之间 `6px`。
- 主按钮放右下，取消放左侧。
- 不在模态框里塞完整页面或多层弹窗。

### 9.2 抽屉

适合查看当前页面的补充信息：冲突详情、任务错误、模组详情。

- 抽屉标题必须带对象名称。
- 保留背景页面上下文。
- 抽屉内的操作不能改变用户对当前对象的定位。

## 10. 编辑器页面

编辑器采用三栏职责：

- 左栏：对象或章节导航
- 中栏：主要创作区域
- 右栏：属性、校验和下一步

中央画布可以使用深色矿物背景，但外层页面保持统一的产品底色。深色画布只承载创作对象，不要把整个页面变成深色。

## 11. 状态和反馈

每个异步动作必须有即时反馈：

- 加载：使用与最终布局相同形状的 Skeleton
- 保存：显示“保存中”到“已保存”
- 后台任务：显示任务名称、所属包和进度
- 错误：在发生位置附近说明原因和下一步
- 删除：二次确认，并明确缓存文件是否保留

未知状态显示 `—`，不能伪装成 `0`。`0` 只表示真实的零值。

## 12. 设计验收

每个页面提交前检查：

- 是否只有一个第一视觉焦点？
- 页面标题是否在一眼内可读？
- 主 CTA 是否明确且只有一个？
- 是否出现不必要的全局指标或装饰卡片？
- 表格数字是否对齐、状态是否可扫读？
- 空态、加载态、错误态是否和正常态使用同一布局语言？
- 是否只使用一套字体、颜色职责和圆角系统？
- 目标视口截图是否和设计稿采用同样的尺寸和裁切？
- 是否通过截图回看，而不只是通过构建检查？
