# web3 编辑能力填充方案（2026-10-03）

> 目标：把 web3 的五个透镜（索引·关系·链路·魔改·编排）从"只读探针"升级为"完整编辑能力"，
> 同时补齐来源面板和底部停靠缺失的操作按钮。
> 原则：**后端 73+ 路由全就绪、api/ 层 1025 行全齐，只写前端 UI，后端一行不改**（模组分类 0027 已做完）。
> 工作量按 step3 原方案的批次拆分，但落到 web3 的新插槽结构里。

## 现状（实测）

| 编排 | ✅ 节点表格 | ❌ 全部 | 无限画布/Inspector/章节编辑 |
| 链路 | ✅ 递归展开+深度分列+机器·时长 | N/A（只读） | 选路逻辑探索 |
| 来源面板 | ✅ 树+搜索+添加+分类 | ⚠️ 启停+分类有，删除/解析/推荐无 | 删除模组、依赖解析、兼容推荐、图标补齐 |

## 分批方案

### 第一批：来源面板 + 构建面板补齐写操作（最高优先，用户最常用）

**来源面板**（SourcesPanel.tsx 增量改）：
1. 模组行加 **删除按钮**（❌ 图标，调 `removeMod()`，弹确认）——删除后 `refresh()`
2. 模组行加 **依赖解析**（来源面板头部或右键，调 `resolvePack()`，进度进底部停靠）
3. 模组行加 **图标补齐**（展开区加"补图标"按钮，调 `resolveModContentIcons()`）
4. 兼容推荐区（来源面板底部）：调 `listModRecommendations()` 列出推荐模组，行级"加装"按钮

**构建面板**（BuildPanel.tsx 增量改）：
5. **导出目录注册**：调 `registerExportDir()`（fs.ts 已有），加目录选择器（调 `browseDir()`）
6. **开始构建**：选中版本后调 `startBuild()`（releases.ts 已有），进度进底部停靠

**底部停靠**（BottomDock.tsx 增量改）：
7. 任务行加 **暂停/继续/取消/重试** 四个操作按钮（调 `pauseTask/resumeTask/cancelTask/retryTask`）

**设置弹窗**（SettingsModal.tsx 增量改）：
8. **清除 CF Key** 按钮（调 `deleteCurseForgeKey()`）

工作量：≈150 行前端，后端零改动。

### 第二批：魔改态完整编辑（3B+3C，工作台的本体）

**关系态**（ModeGraph.tsx 重写）：
1. JEI 网格渲染（`RecipeView` 组件，规格 `jei-recipe-browser.md`）：6 类配方支持
2. 材料点击 → 重新居中（`setFocus` + 关系态不切页）
3. 「魔改此配方」按钮 → `?mode=edit&doc=新建`
4. 已魔改标记（检查 `listContent` 的 applied 覆盖）

**魔改态**（ModeEdit.tsx 从只读探针升级为完整编辑器）：
5. **源 JSON 可编辑**（`textarea` + `JSON.parse` 就地校验）
6. **存草稿**（`saveContentDraft()` + `If-Match` 乐观锁）
7. **校验**（`validateContent()` → issues 按 `path` 定位到 JSON 编辑器对应行）
8. **应用**（`applyContent()` → 成功后 `useCatalog().rebuild()` → 关系态立刻看到"已魔改"）
9. **修订历史 + 回滚**（`contentHistory()` + `rollbackContent()`）
10. **Design|Code 分屏实时预览**（改 JSON 即重画 JEI 网格，复用关系态的 RecipeView）
11. **「应用后生成任务节点」**（`modRefs` 已就绪，一键把配方变成任务节点）

**编排态**（ModeQuest.tsx 升级为无限画布）：
12. **InfiniteCanvas**（拖拽/缩放/连线/吸附，规格 `mp-infinite-canvas.md`）
13. **章节编辑**（侧栏章节行点击可编辑标题/描述）
14. **节点 Inspector**（选中节点 → 侧栏显示属性表单：标题/描述/图标/任务8型/奖励4型/依赖）
15. **保存/校验/应用/回滚**（`saveQuestDraft/validateQuest/applyQuest/rollbackQuest` 全套）
16. **「魔改完配方 → 生成任务节点」**（3C 的 modRefs 落地：编排态画布自动出新节点，预填标题/图标/奖励）

工作量：≈800 行前端（最大的一批，是工作台的核心价值）。
依赖：第一批先做（魔改需要关系态的 RecipeView，编排需要来源面板的分类）。

### 第三批：运行面板 + 发布域 + 商店（交付域完整）

**运行面板**（RunPanel.tsx 升级）：
1. **游戏目录选择器**（调 `browseDir()`，替代手动输入路径）
2. **Java 路径选择**（调 launcher 的 Java 检测/下载）
3. **内存配置**（`xmxMb` 参数）

**发布域**（BuildPanel 扩展或独立）：
4. **发布表单**（CurseForge / Modrinth：项目名/版本号/变更日志/依赖声明）
5. **发布轮询**（提交后 3s 轮询 `pollRelease()`，状态实时更新）
6. **发布重试**（失败后 `retryRelease()`）

**商店面板**（独立或并入来源面板）：
7. **双平台搜索**（已有的 searchAllMods 增强：并发 + 镜像配对 + 下载量排序）
8. **兼容推荐一键加装**（从来源面板搬来）
9. **本地 zip 上传**（`file input` → base64 → `POST /mods/local`）

工作量：≈400 行前端。

### 第四批：包管理 + 系统状态 + 杂项

1. **删包**（包菜单或来源面板，`DELETE /packs/{id}`，需二次确认）
2. **改包重命名**（包菜单，`PATCH /packs/{id}`）
3. **清除 CF Key**（设置弹窗，`DELETE /providers/curseforge/key`）
4. **系统状态卡**（设置弹窗或独立面板，`GET /system/status`）
5. **目录语言切换**（索引工具栏加 locale select，`?locale=` 入 URL）
6. **Evidence 日志入库**（`*.log` → `.txt` 或脚本自产报告）

工作量：≈150 行前端。

## 链路引擎选路（单独探索，不阻塞上面四批）

当前问题：金苹果 → 引擎选了 `gold_block → gold_ingot`（逆向分解，循环方向）。
正确：金苹果 → 8 金锭 → 金矿熔炼 → 金矿采集 + 苹果采集。

根因：`pickRecipe` 对多条同产物配方按"产出量 > 标签少 > id 序"排序，没有"从源头获取"的语义。
可选方案（需深入探索）：
1. **熔炼/高炉优先**：`smelting/blasting` 类是"矿→锭"的正向获取，天然优先于 crafting 分解
2. **输入越"原始"越好**：输入中包含 `*_ore`/`raw_*` 的配方优先
3. **排除循环方向**：如果配方 A 的输入包含 B，且 B 的配方输入包含 A，则标记为互逆对，降优先级
4. **AE2 方式**：完整权重系统（加工步骤数 × 能耗 × 稀有度），过于复杂暂不采

建议：先做 1+2 的简单启发式，实测效果后迭代。链路引擎单独一轮。
