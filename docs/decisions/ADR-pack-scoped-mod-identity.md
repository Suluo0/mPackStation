# ADR：按整合包绑定模组身份、精确版本与内容代次

- 日期：2026-09-08
- 状态：已实施

## 问题

平台项目号、平台版本号和包内记录号都不能代表游戏中的模组 ID。单独按模组 ID 保存当前内容又会让不同整合包、不同版本和不同文件互相污染。Minecraft 原版曾在目录构建阶段单独抓取，因而无法在内容选择器中查看，也缺少与普通模组一致的版本、文件和解析证据。

## 决策

稳定模组身份只使用文件内声明的模组 ID。平台项目与发布记录保留为来源映射，不参与身份拼接。每个整合包通过 `pack_mods` 拥有自己的成员记录，并以 `(pack_id, mod_id)` 限制一个包内只有一个当前模组身份；相同文件和精确版本可由多个整合包共享。

Minecraft 固定使用 `mod_id=minecraft` 和 `origin=builtin`。创建整合包时自动创建该成员，资源准备前处于 pending。目录初始化通过 Mojang 适配器取得并校验指定版本的客户端与语言资源，然后写入文件对象、精确版本、包内选择、内容来源、解析批次和原始定义。目录发布生成不可变代次，并且只有配置修订一致的 ready 代次可以成为整合包当前目录。

现有 `mod_content` 与 `pack_catalog_*` 暂时保留为兼容投影；新写入同时形成版本化证据和目录代次。旧数据在无法从实际文件重新确认身份时保持未决，不生成 `legacy:*`、平台项目前缀或哈希拼接的伪模组 ID。

## 影响

迁移 0015 和 0016 新增身份、平台来源、文件、选择、解析定义和目录代次表，并用复合外键及触发器保护包边界。内容选择器通过 `includeBuiltin=true` 获取 Minecraft；普通模组管理列表继续隐藏内置成员。Minecraft 或加载器配置、模组增删和版本切换都会清空当前目录指针并推进配置修订，旧异步结果不能重新发布为当前数据。
