# web3 · IDE 化单页方案（V3）

> 2026-10-02 用户拍板，取代 v2.1 的「顶栏 + 右栏 + 页面」外壳。v2.1 的减法结论（导航=意图、URL 焦点、禁假 affordance）继续有效；**变的是外壳形态与信息架构的最终收敛**。
> 性质：探针版（v0）——先让外壳以真实数据跑起来给用户看，领域叶子仍按 step3 批次填充。

## 0. 用户决策记录（2026-10-02，原话口径）

1. 整个应用**只有一个屏幕**，页面概念消失：顶边栏一个入口，左侧边栏一个入口。
2. 左侧约 **1/4~1/3** 宽度展示内容；右侧全部是可编辑区域（coding 栏）。
3. 侧栏面板：构建信息、冲突/依赖、焦点物品、事件等，通过**侧栏按钮**切换。
4. 运行日志停靠**底部**（底部可引入 command / 打印日志——后端无 command 端点前不做假输入框）。
5. 布局**不要太网页化**，要像真正的应用；最终 Electron + Go 后端打包（本轮不做，只保证样式方向兼容：密排版、内滚动、固定框架）。
6. 编辑区未来像 Android Studio：图形界面 + coding 界面滑块切换。凡后端有权威 JSON payload 的对象都适用 Design|Code|Split 三态。

- 顶栏 40px：品牌 + **包切换器**（下拉：健康点 + 只看待处理）+ 四个编辑器 tab（仅有包时）+ 问题徽标（✖error ⚠warning，点开=问题面板）+ 任务进度 + ⌘K + ⚙（设置弹窗）。
- 图标轨 44px：焦点 / 来源 / 问题 / 构建 / 运行，五个按钮封顶。**编排态时「来源」面板内容整体换成章节列表**（沿用 v2.1 既定设计）。

## 2. URL 契约（单一事实源，沿用 v2.1 §3.1 的判据）

| 参数 | 含义 |
|---|---|
| `?pack=<id>` | 当前包。缺席 = 编辑区显示迎新（新建/导入 + 四步）。 |
| `?mode=index\|graph\|edit\|quest` | 编辑器 tab，默认 index。 |
| `?tool=focus\|sources\|problems\|build\|run` | 活动侧栏面板，默认 focus。 |
| `?dock=1` | 底部停靠展开。 |
| `?item=` / `?f=&fid=` | 焦点（实现原样迁移 useFocus）。 |
| `?ns=` `?doc=` `?node=` `?q=` | 来源筛选 / 编辑文档 / 任务节点 / 索引搜索。 |

判据不变：任意状态刷新/复制链接，看到的完全一样。

## 4. 实现（web3 探针版）

- **新开 `apps/web3/`，不引用 web2**（沿用 web→web2 的并行惯例；web/web2 保留作对照，均不再动）。
- `src/api/` 整目录从 web2 迁入，零改动（1025 行 + fixtures）。任务日志解析（`fetchTaskLog`）随 launcher.ts 迁入。
- Context 层迁入并做一处适配：`PackSummaryContext` / `CatalogContext` 的 packId 来源从 `useParams().id` 改为 URL `?pack=`（`app/url.ts` 收口）。焦点/迎新/热键原样。
- dev server 固定 **5275**，代理默认回日常后端 18871（`VITE_API_TARGET` 可覆盖）。禁碰 5173/18765/18766/18871 与 `/tmp/mpack-data`。
- 令牌注入同 web2 机制（`VITE_MPACK_TOKEN` 环境变量优先，否则 `data/runtime-token`），禁硬编码。

## 5. 视觉约定（「像应用，不像网页」）

- 基准字号 13px、行高 1.45；面板标题 12px/600；表格行高 26px。
- 圆角 ≤6px（面板 6、控件 4、胶囊 999），边框一律 1px `--mc-line`。
- 整窗 100vh 固定框架，**无页面级滚动**，一切滚动发生在面板/编辑区内部。
- 密排：面板内边距 8~12px，区块间距 8px；禁止大留白居中的「落地页」排版。
- 色彩沿用 tokens.css 暖纸 + ember（品牌不换），语义色不变。
- antd 主题 borderRadius 同步降到 4。

### 挂起：模组搜索（用户拍板「先缓一缓，我得想想怎么整」，方案存档如下）

病因（已实测确诊，证据可复现）：① 平台相关度埋掉 slug-only 正主——raw Modrinth 搜 `ae2` 前 10 全是标题带 AE2 的附属（AE2 标题不含 "ae2"，slug 才是）；② 本地 service 合并后按下载量重排（`service/mods.go:303`）雪上加霜。
方案（讨论已收敛，未实施）：本地复合排序（slug 精确 > 名称分词前缀 > 名称包含 > slug 包含 > 描述 tiebreaker > 下载量）+ 别名表种子（精致存储→sophisticated-storage、应用能源2→ae2 等人工核实条目，长尾靠以后接 MC百科）+ Modrinth slug 直取（`GET /v2/project/{slug}` 200 实测）注入 + 编辑距离 ≤1 容错（aer→ae2）+ 前端 300ms 防抖、最少 2 字符、取消在途请求。
限速实测：Modrinth 响应头 `x-ratelimit-limit: 300`/分钟（按 IP）；CF 按 key 计（本机未配 key，探针 `/tmp/probe-cf-tpm.sh` 就绪）。请求预算：每查询每平台 1 次 + 至多 1 次 slug 直取，复合排序零额外请求。

## 12. 第六轮：# 标签搜索（2026-10-02）

用户定义语法：**`#` = 标签搜索**。`#tools` 应出锄头/斧子/镐——但目录标签体系里没有 "tools" 这个标签（只有 pickaxes/axes/hoes/swords/shovels 各 6 成员），靠**概念表**（TAG_CONCEPTS，与模组别名表同模式的人工核实种子）把概念词展开成标签集合；概念表含编辑距离 ≤1 容错（`#tool`→tools，实测 33 条，概念命中排前）。无概念命中时按标签 ID 匹配（末段精确 > 前缀 > 包含）；空态推荐相关标签（含成员数，点击精确化为 `#<tag>`）。实现于 `app/catalogSearch.ts`（纯函数），UI 在来源下拉的 SearchHits。

顺带修复：✕ 清除按钮此前残留了上一版的绝对定位（钉在面板最右缘压住 ＋），已回归弹性行内、落在 🔍 左侧；✕ 语义 = 只清文字不关闭（上一轮定稿）。

## 13. 第七轮：复杂过滤器（条件构建器，2026-10-02 定稿并实现）

用户拍板：**不做查询语法**（方案 A 否决，「面向用户的，不给系统增加学习成本」），做高级过滤器，替用户把逻辑写好。

- **入口**：索引工具栏的「全部来源」下拉移除，原位换成「复杂搜索」按钮（漏斗图标，带 `启用/总数` 徽标，如 `复杂搜索 2/2`）。
- **条件行**：类型（标签/文本/来源）+ 值（就地编辑，标签带概念词 datalist、来源带命名空间 datalist）+ **启用/禁用**切换 + **仅启**（仅启用这一个，其余全部禁用）+ 删除；可加任意多条。
- **连接词**：全局切换「全部满足（AND）/ 任一满足（OR）」。
- **实时生效**：改动即写 URL（`?f=kind:value:on,...` + `?fmode=and|or` + `?fs=1` 面板开关），刷新/复制链接状态还原；value 可含冒号（解析：首段=类型，末段=启用位，中间=value）。
- **搜索驱动页面**（第一轮遗留问题的最终解法）：索引编辑区的过滤管线 = 复杂条件（?f）→ ?ns= 快捷来源 → ?q= 文本/标签词，全部 AND；`?q=` 以 `#` 开头按标签语义（与来源下拉 # 搜索同一口径）。来源面板的放大镜保持「快速跳转」定位（top30 下拉），列表级筛选统一走复杂过滤器——两个入口、一个引擎。
- **排序**：工具栏新增排序下拉（默认/按名称/按 ID，`?sort=`）。
- 引擎实现：`app/catalogSearch.ts` 的 `parseFilterSpec/encodeFilterSpec/applyFilter`（纯函数，概念展开按查询词 memo）。
- 实测：`tag:tools ∩ text:钻石` = 5 件钻石工具；禁用文本条件 → 30 件全工具；`tag:tools ∪ ns:jei`（OR）+ 按名称排序 = 30 条有序。

## 14. 第八轮：过滤器改 JEI 式前缀（2026-10-02 定稿并实现）

用户反馈两点：① 来源条件不应能填入"不产生内容的模组"（JEI 贡献 0 物品，之前是从测试 URL 强塞进来的）；② 标签输入用 `#` 才符合习惯，不要"标签/文本/来源"类型选择器——**直接给标准输入框，前缀分派**。

- **语法（JEI 习惯）**：`#xxx` = 标签匹配（概念词或标签 ID）、`@xxx` = 来源匹配（模组命名空间）、裸词 = 文本匹配。条件不再存类型，类型从值的前缀**自动派生**，行首徽标三色显示（标签=金、来源=蓝、文本=灰）。
- **建议列表只含真实有贡献的来源**：@ 建议来自目录命名空间（有物品才有条目），不产内容的模组（JEI 类）自然不出现；手工强输 `@jei` 仍合法但命中 0（红标如实显示）。
- **建议列表构成**：# 概念词（tools/工具/armor…）+ @ 真实来源（前 12，带物品数）+ 成员最多的 20 个标签（带成员数）。
- 编辑区 `?q=` 同步支持三种前缀（与过滤器同一口径）。
- URL 契约变更：`?f=value:on,...`（值自带前缀，解析=末段启用位、其余为值）；旧 `kind:` 前缀格式废弃（功能存活几分钟，无兼容负担）。
- 实测：`#tools ∩ @minecraft` = 30（全部工具都是原版），徽标命中数正确。

### 第九轮：输入框建议 + 双击速览 + 排序方向（2026-10-02）

1. **原生 datalist 弃用**：三角箭头丑且不居中 → 自绘 `SuggestInput`（聚焦/输入时向下弹出，15 行内滚动，值 + 说明两列，Esc 关闭；行按下即填充）。
2. **双击不再顶掉页面**：双击物品格 = 从格子向下弹 `ItemQuickView`（440px，头部图标/名称/ID + 「看关系」+ ✕，正文「作为产物/作为原料」逐条配方，≈15 行封顶滚动）；单击仍是选中，Enter 仍进关系态。
3. **滚动条全局统一**：`base.css` 定体系（10px 含 3px 透明衬边、暖灰圆角、透明轨道、悬停加深），所有滚动区（含浮层）一套视觉。

### 目录数据确诊（用户报告"很多没名字的 diamond_boots_gold_trim / 数量不对"，已用真实目录数据实锤）
