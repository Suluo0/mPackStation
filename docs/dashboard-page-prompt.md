# 提示词：整合包工作台 · 看板页面（Dashboard）详细设计

> 用途：把本文件整段作为提示词交给前端实现 agent，要求其产出一个**生产可用**的看板页面。
> 本文件自含全部设计要求，不需要也不允许参考仓库里任何旧文档、旧页面、旧设计规范——那些是早期探索的遗留物，不代表当前产品方向。一切以下文为准。

---

## 0. 你是谁、要做什么

你是一名资深前端工程师 + 产品设计师。我们要做一个 **Minecraft 整合包设计工作台**（Web 应用，React 单页应用）。它的核心理念是：

- **整合包（Modpack）是唯一的工作对象**。用户不是在"管理一个模组库"，而是在"设计一个个整合包"。
- 平台的价值是**解决问题**，不是陈列信息。用户要看到"已解决"，而不是"不兼容"。
- 用户全程**不需要启动游戏、不需要打开外部编辑器**：搜索模组、管理内容、改配方、改结构生成、配任务书、一键打包，全部在站内完成。

你要实现的是这个工作台的**看板页（Dashboard）**——应用的默认首页 / 启动落地页。

看板页承担两个截然不同的职责，必须都做好：

1. **迎新**：用户首次启动（还没有任何整合包）时，它是欢迎页 + 引导页，要在 10 秒内让用户明白这是什么工具、第一步该干什么。
2. **数据总览**：用户已有整合包时，它是数据驾驶舱，要在 3 秒内回答三个问题：
   - **我该干什么**（下一步动作）
   - **我的包健康吗**（状态信号）
   - **后台在忙什么**（任务进度）

---

## 1. 技术约束

- 技术栈：**React 18 + TypeScript + react-router-dom + Ant Design 5（antd）+ zod**（接口数据校验）。
- 路由：`/` 即看板页。页面组件名 `DashboardPage`。
- 所有数据通过后端 REST API 获取（本提示词第 5 节定义了数据契约；实现时用 zod schema 校验响应，接口未就绪时以 mock 数据驱动，mock 与真实接口之间只允许隔一层 `api/dashboard.ts`）。
- 不允许引入新的重型依赖（如图表库用 antd 自带的轻量组件或纯 CSS 进度条即可，本页**不需要图表库**）。
- 设计资源（颜色、圆角、间距、字号）在**本文件第 6 节**完整给出，直接按它实现一套 CSS 变量，不要去找别处的规范。

---

## 2. 设计原则（不可妥协）

1. **包为中心**。看板上只允许出现"和整合包有关"的数据。**禁止**出现全局虚荣指标，例如"平台共收录 83,262 个模组"——那不是用户的成就，是噪音。
2. **信号优先于数据**。用户要的是"待解决 3"这样一个刺眼的数字，不是一张模组明细表。明细永远属于二级页面。
3. **"已解决"要和"待解决"成对出现**。例如冲突计数永远渲染为 `已解决 12 · 待解决 3`，前者给成就感，后者给行动指引。这是产品价值观的直接体现。
4. **下一步动作永远可见**。无论空态还是有数据，首屏必须有一个明确的主按钮告诉用户此刻最该做什么。
5. **后台任务必须透明**。后台在索引、在打包时，看板必须显示进度；静默的后台 = 用户以为卡死。
6. **空态不是"暂无数据"**。空态是迎新页，是产品第一次和用户说话，要热情、具体、有引导，而不是一个灰色的 Empty 图标。

---

## 3. 页面两种状态

页面根据"是否存在整合包"分为两个状态，**布局结构完全不同**，不是同一张表的空数据兜底：

- **空态（Onboarding）**：`packs.length === 0` → 渲染第 4.1 节的迎新布局。
- **有包态（Dashboard）**：`packs.length > 0` → 渲染第 4.2 节的数据看板布局。

此外有贯穿两种状态的**环境自检条**（4.0），以及加载态/错误态（4.3）。

---

## 4. 页面结构与布局详述

整体为顶部应用栏（各页面共享，不属于本页范围）之下的**单栏纵向滚动页**，内容最大宽度 1200px 居中，左右留白自适应。所有卡片为白色底、6px 圆角、1px 浅灰描边、极轻投影（规格见第 6 节）。

### 4.0 环境自检条（两种状态都可能出现）

- 位置：页面最顶部，内容区全宽。
- 默认**不渲染**。只有当自检发现问题时出现，一条一条列出，可关闭（关闭后本次会话不再出现，问题仍存在时下次启动再出现）。
- 样式：警示黄底条（`--mc-gold-bg` 底、`--mc-gold` 文字），左侧警告图标，右侧"去处理"链接按钮 + 关闭按钮。
- 检查项与文案：
  - **CurseForge API Key 未配置** → "CurseForge API Key 未配置，将无法检索 CurseForge 模组。→ 去设置"
  - **Modrinth 连通失败** → "Modrinth 当前无法连接，搜索将只返回 CurseForge 结果。→ 重试"
  - **CurseForge 连通失败** → 同上对称。
  - **存储目录不可写 / 磁盘剩余 < 5GB** → "存储空间不足（剩余 X），可能无法下载模组。→ 查看存储设置"
- 数据来源：`GET /api/system/health`（见 5.4）。

### 4.1 空态 · 迎新布局

从上到下四个区块：

**(a) 欢迎区 Hero**

- 居中排版，上下各 64px 留白。
- 第一行：产品名 + 品牌图标（品牌渐变色方块图标，见第 6 节）。
- 第二行：主标语（一级标题）：**"从搜索到打包，不启动游戏，完成你的整合包"**。
- 第三行：副标语（正文色偏灰）："双平台检索 · 依赖自动锁定 · 冲突自动解决 · 配方/结构/任务书在线配置 · 一键打包"。
- 第四行：主按钮（大号主按钮）：**"新建第一个整合包"**，点击 → 弹出新建整合包对话框（见 4.4）。

**(b) 三个入口卡片**

- 一行三列（窄屏纵向堆叠），等宽卡片，hover 时描边变主色、轻微上浮（translateY -2px + 投影加深），整张卡可点击。
- 卡片 1 · **新建整合包**：图标（加号/盒子），一句话"从零开始：选版本、选加载器，边搜边加"，按钮文字"开始创建"。
- 卡片 2 · **导入现有整合包**：图标（导入/箭头入盒），一句话"从 CurseForge / Modrinth / 本地 zip 导入，接着改"，按钮文字"导入"。注意：导入与新建筑**并列同级**，不允许藏在二级入口——大多数作者是从已有包开始的。
- 卡片 3 · **浏览示例包**：图标（眼睛/罗盘），一句话"看看一个设计完成的整合包长什么样"，按钮文字"看看"。点击进入一个内置只读示例包的工作台（无后端时可用纯前端 mock）。

**(c) 能力流程条**

- 一条横向四步流程（窄屏改为两行两列）：**选**（搜索筛选模组）→ **锁**（版本与依赖锁定）→ **改**（配方/结构/任务书在线编辑）→ **装**（一键打包安装）。
- 每步：圆形序号徽标（品牌渐变）+ 步骤名（二级标题）+ 一句话说明（小字灰色，不超过 20 字）。
- 步骤之间用浅色箭头或连线连接。
- 目的：10 秒建立"这个工具能干什么"的心智模型。纯展示，无交互。

**(d) 新手清单（Checklist）**

- 卡片标题"上手三步"，内容为一列可勾选项：
  1. ✅/⬜ 配置 CurseForge API Key（完成后自动打勾；未完成时右侧有"去配置"链接）
  2. ✅/⬜ 创建或导入第一个整合包
  3. ✅/⬜ 添加第一个模组
- 每项完成态：文字变灰 + 删除线 + 绿色对勾。
- 全部完成时整张卡消失（以后也不再出现），用一句话"🎉 上手完成"toast 替代一次。
- 完成状态存后端（`GET/PUT /api/onboarding`），不做纯 localStorage 实现。

### 4.2 有包态 · 数据看板布局

从上到下五个区块：

**(a) 页头行**

- 左侧：一级标题"工作台"，其下小字灰标语"N 个整合包 · 今日已解决 M 个问题"。
- 右侧两个按钮：次按钮"导入整合包"、主按钮"新建整合包"。

**(b) 继续工作卡（视觉权重最高）**

- 占内容区全宽，高度约 120px，比其他卡片更强的存在感（可用品牌渐变的左侧 4px 竖条标识）。
- 内容 = **最近编辑的那个包**：
  - 左侧：包图标（用户上传或首字母渐变占位）、包名（二级标题）、其下小字：`MC 1.20.1 · NeoForge · 142 个模组 · 最后编辑 2 小时前`。
  - 中部：该包的**健康信号条**（横向排列的一组小指标，详见 4.2.1 信号规范）：冲突 `已解决 12 · 待解决 3`、内容编辑 `配方 8 · 结构 2 · 任务 15`、告警 `崩溃 0 · 可更新 5`。
  - 右侧：大号主按钮 **"继续设计 →"**，点击进入该包的工作台页面。
- 如果存在**进行中的后台任务**（如正在打包、正在索引），按钮上方加一行小字进度提示："后台：正在为 X 包索引模组数据（3/5）"。

**(c) 整合包列表（全部包的健康一览）**

- 卡片标题"全部整合包"，右上角小字链接"管理"。
- 内容：**每包一行**的行式列表（不是大卡片网格——包可能很多，行式扫读最快）。每行从左到右：
  1. 包图标 + 包名（正文加粗）+ 版本号徽章（如 `v1.2.0`，灰色小徽章）
  2. 环境标签：`MC 版本` + `加载器` 两个小胶囊
  3. 模组数：`142 模组`（含细分 tooltip：已安装 130 · 已选择未装 12）
  4. **冲突信号**：`已解决 12 · 待解决 3`（待解决 > 0 时数字红色加粗；= 0 时整组灰色低调）
  5. **内容编辑量**：`配方 8 · 结构 2 · 矿脉 1 · 任务 15`（小字灰色）
  6. **告警**：有崩溃未处理 → 红色"崩溃 2"；有可更新模组 → 蓝色"可更新 5"；无则不渲染
  7. 最后编辑时间（小字灰色，相对时间）
  8. 行尾操作：主链接"打开"，更多菜单（⋯）：重命名 / 复制包 / 导出一键打包 / 删除（删除必须二次确认弹窗，文案写明"不会删除已下载的模组文件缓存"）
- 整行可点击 = 打开该包工作台。
- 行 hover：浅蓝底。
- 行内任何数字都不允许换行，宽度不足时中间信息截断、信号列优先保留。
- 默认按最后编辑时间倒序。无搜索框（包数量级是几十个，不需要）。

**(d) 后台任务区**

- 卡片标题"后台任务"，仅当存在任务（进行中或最近完成/失败）时渲染；长期无任务时整块隐藏。
- 每个任务一行：任务名（如"索引 Create 模组数据层"）、所属包名、进度条 + 百分比、状态胶囊（进行中=紫色"运行中" / 成功=绿色"已完成" / 失败=红色"失败" / 已取消=灰色）。
- 进行中任务的行尾操作：暂停 / 取消。失败任务的行尾操作：**重试** / 查看错误（点击展开错误详情抽屉）。
- 任务类型至少包括：模组数据层索引（模组进包时）、整合包打包、整合包导入解析、模组更新预演。
- 数据来源：`GET /api/tasks?recent=20`，进行中任务每 3 秒轮询一次，无进行中任务时停止轮询。

**(e) 环境与动态（弱存在区）**

- 一行两列（窄屏堆叠）两张矮卡片：
  - **环境状态**：双平台连通性（Modrinth ✅ / CurseForge ✅ 小圆点+文字）、索引库占用（"数据缓存 1.2 GB"）、存储剩余。全部正常时全部灰色低调；异常项用警示色。
  - **最近动态**：最近 10 条活动的流式列表，每条一行：相对时间 + 动作描述，如"10:32 向「科技魔法」添加了 JEI"、"10:35 自动解决了 2 个配方冲突"、"昨天 打包「科技魔法」v1.2.0 成功"。动态类型配色：添加=蓝、解决=绿、打包=紫、告警=红。**"解决"类动态必须有**，它是产品价值观的展示窗。
- 数据来源：`GET /api/system/status`、`GET /api/activities?limit=10`。

#### 4.2.1 健康信号规范（全站统一的信号语义）

看板用到的信号计数以本规范为准，其他页面将来也复用：

| 信号 | 格式 | 颜色规则 |
|---|---|---|
| 冲突 | `已解决 N · 待解决 M` | M>0 时 M 红色加粗；M=0 全灰 |
| 崩溃 | `崩溃 N` | N>0 红色；N=0 不渲染 |
| 可更新 | `可更新 N` | 蓝色；N=0 不渲染 |
| 内容编辑 | `配方 a · 结构 b · 矿脉 c · 任务 d` | 全灰小字；全 0 时显示"尚未编辑" |
| 任务状态 | 文字胶囊 | 运行中=紫、成功=绿、失败=红、取消=灰 |

### 4.3 加载与错误态

- 首次加载：整页骨架屏（Skeleton），按 4.2 布局的轮廓占位，不用转圈 spinner。
- 某区块接口失败：该区块内联错误条 + "重试"按钮，**不影响其他区块渲染**。
- 健康信号接口失败：信号列显示"-"，不显示 0（0 是真实状态，- 是未知）。

### 4.4 新建整合包对话框（本页的直接子功能）

看板页内嵌实现，表单字段：

- **包名称**（必填，≤ 50 字，实时校验重名）
- **MC 版本**（必填，下拉，数据源 `GET /api/meta/mc-versions`，支持输入过滤）
- **加载器**（必填，单选卡片式：Forge / NeoForge / Fabric / Quilt，每项带图标 + 一句话差异提示）
- **包描述**（选填，多行，≤ 200 字）
- 底部提示一行小字："版本与加载器创建后将成为整个包的作用域，修改将触发全包重解。"
- 提交 → `POST /api/packs` → 成功后直接进入新包工作台。

### 4.5 导入整合包对话框

- 三种来源 Tab：**CurseForge 链接 / Modrinth 链接 / 本地 zip 文件**。
- 链接类：粘贴框 + "解析"按钮 → 解析出包名、版本、模组数后显示预览卡 → "确认导入"。
- 本地类：拖拽上传区 + 文件选择。
- 导入后：跳到后台任务区可见"导入解析"任务，完成后 toast 提示并刷新列表。

## 5. 数据契约（后端接口定义）

以下为前端期望的接口形状。字段命名即最终命名，后端不匹配时由 `api/dashboard.ts` 适配层转换，组件内不允许直接处理原始响应。

### 5.1 `GET /api/dashboard` → 看板主数据

```ts
{
  packs: Array<{
    id: string
    name: string
    iconUrl: string | null
    mcVersion: string          // "1.20.1"
    loader: 'forge' | 'neoforge' | 'fabric' | 'quilt'
    packVersion: string        // "1.2.0"
    modCount: { total: number; installed: number; selected: number }
    conflicts: { resolved: number; pending: number }
    edits: { recipes: number; structures: number; ores: number; quests: number }
    alerts: { crashes: number; updatable: number }
    lastEditedAt: string       // ISO 8601
    createdAt: string
  }>
  lastEditedPackId: string | null
  todayResolvedCount: number   // 今日已解决问题数
}
```

### 5.2 `GET /api/tasks?recent=20` → 后台任务

```ts
Array<{
  id: string
  type: 'index-mod' | 'build-pack' | 'import-pack' | 'update-preflight'
  title: string               // "索引 Create 模组数据层"
  packId: string | null
  packName: string | null
  status: 'running' | 'success' | 'failed' | 'cancelled' | 'paused'
  progress: number            // 0-100
  error: string | null
  startedAt: string
  finishedAt: string | null
}>
```

### 5.3 `GET /api/activities?limit=10` → 最近动态

```ts
Array<{
  id: string
  kind: 'add-mod' | 'resolve' | 'build' | 'alert' | 'edit' | 'import'
  text: string                // "向「科技魔法」添加了 JEI"
  packId: string | null
  at: string                  // ISO 8601
}>
```

### 5.4 `GET /api/system/health` + `GET /api/system/status`

```ts
// health：环境自检，所有项 ok=true 时前端不渲染自检条
{
  curseforgeKeyConfigured: boolean
  modrinthReachable: boolean
  curseforgeReachable: boolean
  storageWritable: boolean
  storageFreeBytes: number
}

// status：环境状态卡
{
  modrinthReachable: boolean
  curseforgeReachable: boolean
  cacheSizeBytes: number
  storageFreeBytes: number
}
```

### 5.5 `GET/PUT /api/onboarding`

```ts
{ steps: { curseforgeKey: boolean; firstPack: boolean; firstMod: boolean } }
```

### 5.6 `POST /api/packs`、`POST /api/packs/import`

创建/导入的请求响应按 REST 惯例实现，前端以 zod 校验。

## 6. 设计规范（本页自含，直接照做）

在页面样式文件顶部定义这组 CSS 变量并全程引用，不允许散落硬编码值：

```css
:root {
  /* 圆角 */
  --mc-radius: 6px;          /* 卡片、按钮、输入框、徽章统一 */
  --mc-radius-pill: 999px;   /* 仅状态小圆点、头像 */

  /* 间距刻度 */
  --mc-sp-xs: 8px; --mc-sp-sm: 12px; --mc-sp: 16px; --mc-sp-lg: 24px;

  /* 颜色 */
  --mc-text: #172033;        /* 主文本 */
  --mc-muted: #8993a4;       /* 次要/标签文本 */
  --mc-bg: #f5f7fb;          /* 页面底 */
  --mc-fill: #ffffff;        /* 卡片底 */
  --mc-line: #eef1f6;        /* 弱描边/分隔线 */
  --mc-hover: #eaf2ff;       /* 行 hover */
  --mc-blue: #1677ff;        /* 信息蓝：主按钮、链接、可更新信号 */
  --mc-blue-bg: #eaf2ff;
  --mc-accent: #7c3aed;      /* 品牌紫：运行中状态、序号徽标 */
  --mc-accent-bg: #f3edff;
  --mc-success: #16a34a;     /* 成功/已解决 */
  --mc-success-bg: #e9f7ef;
```

字体层级：

| 层级 | 规格 | 用途 |
|---|---|---|
| 一级标题 | 24px / 700 | 页头"工作台"、迎新主标语 |
| 二级标题 | 16px / 600 | 卡片标题、包名、步骤名 |
| 正文 | 14px / 500 | 默认文本 |
| 小字 | 12px / 500 | 标签、次要信息、时间 |
| 大数值 | 20px / 600 | 信号计数的数字 |

配色语义纪律：

- **蓝 = 交互与信息**（链接、主按钮、可更新）。
- **紫 = 品牌与进行态**（运行中、序号徽标、渐变图标）。
- **绿 = 已解决/成功**。红 = 待解决/失败/崩溃。金 = 环境警示。
- "已解决"绿色永远先于"待解决"红色出现，视觉上先扬后警。

## 7. 交互与行为细则

1. 所有相对时间（"2 小时前"）超过 7 天改为绝对日期。
2. 包行"删除"：Popconfirm 二次确认，确认后乐观移除该行，失败回滚并 toast 错误。
3. 任务轮询：仅在有 `running` 状态任务时启动 3s 轮询；页面不可见（document.hidden）时暂停。
4. 空态三个入口卡的 hover 动效走 `--mc-dur`/`--mc-ease` 令牌（160ms）；禁用花哨动画，全页动效只有 hover 上浮、按钮按压反馈和进度条过渡。
5. 所有按钮点击后立即给反馈（loading 态或跳转），不允许无响应等待。
6. 数字格式化：≥ 1000 显示为 `1.2k`；字节显示为 `GB/MB` 一位小数。
7. 移动端不追求完整适配，但 ≤ 768px 时：三入口卡纵向堆叠、包行的"内容编辑量"列隐藏、继续工作卡纵排。
8. 页面标题（document.title）："工作台 · MC 整合包设计工具"。

## 8. 验收标准（实现完成后逐条自检）

1. 空态下：欢迎语、三入口卡、四步流程、新手清单全部渲染；无任何"暂无数据"式灰色空壳。
2. 环境异常（如 CF Key 未配）时自检条出现且"去处理"链接可达；全部正常时自检条不存在于 DOM。
3. 有包态：继续工作卡展示的是 `lastEditedPackId` 对应的包；点击"继续设计"跳转到 `/packs/:id`。
4. 包列表每行的冲突信号严格按 4.2.1 配色规则渲染：`待解决 > 0` 红、`= 0` 灰。
5. 后台任务区在有 running 任务时每 3 秒刷新且进度条推进可见；无任务时整个区块不存在于 DOM。
6. 删除包有二次确认；新建对话框的版本/加载器必填校验生效。
7. `tsc` 编译零错误、`eslint` 零警告；页面在无后端时以 mock 数据完整渲染两种状态（通过 mock 开关切换空态/有包态各截图验证）。
8. 全页颜色/圆角/间距只引用第 6 节变量，grep 不到十六进制硬编码颜色（变量定义处除外）。
