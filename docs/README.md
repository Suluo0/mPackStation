# docs/ 目录结构

按职能分子目录。新增文档请放进对应目录，不要堆在 `docs/` 根目录。

| 目录 | 职能 | 内容 |
| --- | --- | --- |
| `architecture/` | 后端架构设计与评审 | v7 权威架构、三份合并草案、v6 参考稿、能力草案 |
| `design/` | 视觉与设计系统 | Design System、视觉语言、看板页面规格（含 6.1 视觉规范） |
| `design/baseline/` | 视觉基准资产 | 用户验收用的设计稿原件 |
| `standards/` | 开发、测试与构建规范 | 开发规范、开发顺序、测试验收标准、构建与部署 |
| `specs/` | 页面规格（唯一真相） | 每页一份自含规格：行为 + 数据契约 + 设计令牌 + 验收标准 |
| `issues/` | 问题单 | 按阶段编号的问题记录 |
| `reviews/` | 评审报告 | 交叉评审与外部盲审输出 |
| `tests/` | 验收证据 | 测试矩阵、分阶段验收记录、测试报告审计 |
| `project-state/` | 项目检查点 | `state.json`、`HANDOFF.md`、`history/` 会话记录 |

## 约定

- **不写本机绝对路径。** 文档内部引用一律用仓库相对路径。机器相关信息（本机路径、工具链位置、端口占用、进程 PID）属于记忆层，不进仓库——它们既会泄露环境信息，也会随环境变化而失效。
- **视觉基准图入库。** 验收基准放在 `design/baseline/`，用仓库相对路径引用；不要引用仓库外的路径（文件一移动引用就断）。
- **页面规格是唯一真相。** `specs/` 下每页一个自含文档，mock 先行，截图验收通过后才接真实后端；AI 生成的效果图只是视觉参考，其内部文字不可信。
- **状态文档会过期。** `project-state/` 记录的是某一时刻的快照；判断当前进度以代码和 `git log` 为准。
