# docs/ 目录结构

按职能分子目录。新增文档请放进对应目录，不要堆在 `docs/` 根目录；**完成使命的历史文档**（旧版方案、一次性评审、带日期的审计快照、历史会话记录）移入 `archive/`。

| 目录 | 职能 | 内容 |
| --- | --- | --- |
| `architecture/` | 后端架构设计 | v7 权威架构（三份草案合并后的执行版）、v6 参考稿、launcher-core 架构、表结构设计 |
| `api/` | 接口契约 | contract / dto / errors / auth / standards、集成矩阵、实现状态 |
| `design/` | 视觉与设计系统 | Design System、视觉语言、现行特性设计稿（web3 外壳、关系透镜、物品图标渲染器等） |
| `design/baseline/` | 视觉基准资产 | 用户验收用的设计稿原件 |
| `design/prototype/` | 交互原型 | 可打开的关系透镜 HTML 原型 |
| `standards/` | 开发、测试与构建规范 | 开发规范、开发顺序、测试验收标准、构建与部署 |
| `specs/` | 页面规格（唯一真相） | 每页一份自含规格：行为 + 数据契约 + 设计令牌 + 验收标准 |
| `issues/` | 问题单 | 按阶段编号的问题记录（P1-P7、DB、FE、HTTP） |
| `tests/` | 验收证据 | 测试矩阵、分阶段验收记录、缺陷台账、证据日志 |
| `project-state/` | 项目检查点 | `state.json`、`HANDOFF.md`（持续更新的交接文档） |
| `decisions/` | 架构决策记录 | ADR：包内容目录、包域模组身份 |
| `user_check/` | 用户反馈排查记录 | 口述问题的排查确认与修复台账 |
| `archive/` | 历史文档归档 | 完成使命的过程文档，只读参考——见 `archive/README.md` |

## 约定

- **不写本机绝对路径。** 文档内部引用一律用仓库相对路径。机器相关信息（本机路径、工具链位置、端口占用、进程 PID）属于记忆层，不进仓库——它们既会泄露环境信息，也会随环境变化而失效。
- **视觉基准图入库。** 验收基准放在 `design/baseline/`，用仓库相对路径引用；不要引用仓库外的路径（文件一移动引用就断）。
- **页面规格是唯一真相。** `specs/` 下每页一个自含文档，mock 先行，截图验收通过后才接真实后端；AI 生成的效果图只是视觉参考，其内部文字不可信。
- **状态文档会过期。** `project-state/` 记录的是某一时刻的快照；判断当前进度以代码和 `git log` 为准。
- **过时即归档。** 文档被新版本取代、或描述的工作已完成后，移入 `archive/`（保留原子目录名），不要原地堆积或在旧文档里续写。
